# 도서관 스터디룸 모바일 예약 시스템

인원과 시간만 고르면 지금 예약할 수 있는 빈 방을 보여주는 모바일 웹 예약 서비스입니다.

**배포 링크:** https://sungbin23.github.io/studyroom-reservation/

UX/UI 수업에서 작성한 기획을 서버 없이 동작하는 웹사이트로 구현했습니다. 스터디룸 데이터는 목업이며, 예약 내역은 사용하는 브라우저에만 저장됩니다.

## 기획 배경과 문제

조별 과제 장소를 급히 찾는 학생은 약 10분의 쉬는 시간에 복잡한 복도를 걸으며 한 손으로 예약합니다. 기존 예약 화면은 PC용 가로 시간표(Time-grid)를 그대로 축소해 보여주기 때문에 오터치와 예약 포기가 반복되었습니다.

| 메모 | 관찰된 문제 | 이 서비스의 해결 방법 |
| --- | --- | --- |
| M01 | 깨알 같은 표를 핀치 줌으로 확대함 | 표를 없애고 방 번호와 수용 인원을 크게 표시 |
| M02 | 14시를 누르려다 14시 30분을 오터치함 | 간격을 둔 시간 다이얼과 예약 전 최종 확인 |
| M03 | 표가 잘려 휴대폰을 가로로 돌림 | 세로 화면 우선 설계, 가로 스크롤 없음 |
| M04 | 방 번호만으로는 몇 인실인지 모름 | 카드마다 "4인실"을 크게 표시 |
| M05 | 햇빛 아래서 빈칸과 예약 칸이 구분되지 않음 | 글자 대비 4.5:1 이상, 아이콘과 글자로 상태 병행 표시 |
| M06 | 방이 없으면 다른 앱으로 이탈함 | 같은 화면에서 인접 시간대의 빈 방 추천 |
| M07 | 뒤로가기를 누르면 처음으로 초기화됨 | 직전 단계로 이동하고 선택 조건 유지 |
| M08 | 방을 바꾸기보다 30분 늦게 모이는 쪽을 택함 | "30분 후"를 첫 번째로 추천 |
| M09 | 인원수부터 고르고 남는 방만 보고 싶어 함 | 인원을 먼저 고르고 빈 방만 표시 |
| M10 | 오터치 끝에 예약을 포기함 | 큰 버튼과 쉬운 되돌리기 |

## 주요 기능

- **인원 스테퍼와 빠른 선택 칩:** 1~8명을 스테퍼로 고르고, 자주 쓰는 2·4·6명은 칩으로 바로 선택합니다.
- **날짜와 시간 다이얼 조건 필터링:** 오늘부터 14일 중 날짜를 고르고, 시작 시간은 세로 다이얼로, 이용 시간은 1/2/3시간 버튼으로 선택합니다.
- **빈 방 카드 리스트:** 선택 인원 이상 수용할 수 있는 빈 방만 작은 방부터 보여줍니다. 전체 시간표는 표시하지 않습니다.
- **인접 시간 추천:** 빈 방이 없으면 30분 후, 30분 전, 1시간 후, 1시간 전의 빈 방을 추천합니다.
- **확인 바텀시트:** 방, 날짜, 시간, 인원을 크게 보여주고 "확인" 또는 "다시 고르기"를 선택합니다.
- **티켓형 QR 완료 화면:** 출입용 QR코드와 예약 정보를 티켓 카드로 보여줍니다.
- **뒤로가기 조건 유지:** 브라우저 뒤로가기와 "이전" 버튼 모두 직전 단계로 이동하며, 새로고침해도 조건이 유지됩니다.
- **승인 실패 복구:** 네트워크 문제로 확정하지 못해도 고른 내용을 유지한 채 다시 시도할 수 있습니다.
- **테스트 모드:** 기획 지표인 완료 시간, 오터치·취소 횟수, 복구 시간을 화면에서 측정합니다.

## 화면 흐름

| 단계 | 화면 | 설명 |
| --- | --- | --- |
| 1/3 | 조건 입력 | 인원, 날짜, 시작 시간, 이용 시간을 차례로 고르고 "빈 방 찾기"를 누릅니다. |
| 2/3 | 빈 방 리스트 | 조건에 맞는 방 카드에서 "예약하기"를 누릅니다. |
| 2/3 | 빈 방 없음 (예외) | 인접 시간대 추천 카드에서 바로 예약합니다. |
| 2/3 | 확인 바텀시트 | 예약 내용을 확인하고 확정합니다. |
| 3/3 | 예약 완료 | 티켓 카드의 QR코드를 입구에서 보여줍니다. |

## 기획 지표와 검증 방법

목표값은 기획서에 가상값으로 설정한 수치입니다. 화면 하단의 **테스트 모드**를 켜고 예약을 진행하면 측정 결과와 달성 여부가 표시됩니다.

| 지표 | 목표 | 측정 방법 |
| --- | ---: | --- |
| 과업 완료 시간 | 30초 이하 | 첫 터치부터 예약 완료까지의 시간 |
| 오터치·취소 횟수 | 0회 | 뒤로가기("이전" 포함)와 "다시 고르기"를 누른 횟수 |
| 오류 후 복구 시간 | 5초 이하 | 되돌린 순간부터 다시 앞 단계로 나아갈 때까지의 최장 시간 |

## 시연 방법

오늘 날짜는 지난 시간을 고를 수 없으므로 **내일 이후 날짜**로 시연하는 것을 권장합니다. 예약 시간은 요일별로 고정되어 있어 같은 조건이면 언제나 같은 결과가 나옵니다.

**빈 방 없음 화면**

| 조건 | 결과 |
| --- | --- |
| 8명, 월~금 또는 일요일, 15:00, 1시간 | 빈 방 없음, 인접 시간대 추천이 모두 표시됨 |
| 8명, 월~금 또는 일요일, 15:00, 2시간 | 빈 방 없음, 추천과 "여기도 꽉 찼어요"가 함께 표시됨 |
| 8명, 토요일, 15:00, 1시간 | 빈 방 없음, 근처 시간대도 없어 조건 변경 안내가 표시됨 |

**승인 실패 재현**

1. 화면 맨 아래의 "테스트 모드"를 켭니다.
2. "승인 실패 재현" 버튼을 눌러 "승인 실패 대기 중" 상태로 만듭니다.
3. 예약을 진행해 바텀시트에서 "확인"을 누릅니다.
4. 실패 안내가 나오고 선택 내용이 유지됩니다. "다시 시도"를 누르면 예약이 완료됩니다.

## 개발 과정

1. **최초 구현:** 조건 입력, 빈 방 리스트, 인접 시간 추천, 확인, QR 완료까지의 흐름과 테스트 모드를 구현했습니다.
2. **기획서 대조 수정:** 작업분석 문서의 To-be 흐름, HTA, 요구사항 표와 대조해 시간 다이얼, 복구 시간 측정, 승인 실패 처리, "30분 후" 우선 추천을 반영했습니다.
3. **사용성 피드백 반영과 디자인 개선:** 홀수 인원 예약이 필요하다는 피드백으로 인원 스테퍼를 추가하고, 카드형 UI, 하단 고정 버튼, 바텀시트, 티켓형 완료 화면으로 디자인을 개선했습니다.

## 기술 스택과 폴더 구조

- HTML, CSS, JavaScript (빌드 도구와 서버 없음)
- History API, localStorage, sessionStorage
- [qrcodejs](https://github.com/davidshimjs/qrcodejs) (QR코드 생성), [Pretendard](https://github.com/orioncactus/pretendard) (폰트), CDN으로 불러옴

```text
.
├── index.html       화면 틀
├── style.css        디자인 토큰과 스타일
├── data.js          스터디룸 목업 데이터
├── app.js           화면 동작과 예약 로직
├── CLAUDE.md        기획 요약과 구현 규칙
├── README.md
└── docs/            기획 문서와 대조표
```

## 로컬 실행 방법

프로젝트 폴더에서 정적 서버를 실행한 뒤 브라우저로 접속합니다.

```bash
python -m http.server 8000
```

http://localhost:8000/ 에 접속하면 됩니다. QR코드와 폰트는 CDN에서 불러오므로 인터넷 연결이 필요합니다. 휴대폰 화면으로 보려면 브라우저 개발자 도구의 기기 모드를 사용합니다.
