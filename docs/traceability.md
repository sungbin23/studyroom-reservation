## 3. 요구사항과 지표 (Ch.06 §7, Ch.03 §5)

목표값은 기획서에 "가상"으로 표시된 값입니다. 사이트는 측정 기능을 제공하며, 실제 달성 여부는 사용자 테스트로 확인해야 합니다.

| 기획서 항목 | 구현한 화면/기능 | 관련 파일 |
| --- | --- | --- |
| 요구사항 1: 인원과 시간만 입력하면 빈 방 목록 | 조건 입력 후 빈 방 리스트 표시 | `app.js`, `data.js` |
| 지표: 과업 완료 시간 30초 이하 | 테스트 모드에서 첫 터치부터 예약 완료까지 측정하고 달성 여부 표시 | `app.js`, `index.html` |
| 요구사항 2: 크고 넉넉한 버튼 | 모든 터치 영역 48px 이상, 인접 버튼 간격 8px 이상 | `style.css` |
| 지표: 오터치 및 취소 횟수 0회 | 테스트 모드에서 뒤로가기와 다시 고르기 횟수를 측정하고 달성 여부 표시 | `app.js` |
| 요구사항 3: 초기화 없이 직전 단계로 복귀 | History API로 단계마다 기록. 조건은 그대로 유지 | `app.js` |
| 지표: 오류 후 복구 시간 5초 이하 | 테스트 모드에서 되돌린 순간부터 다시 앞으로 진행할 때까지의 최장값을 측정하고 달성 여부 표시 | `app.js` |

## 4. 관찰 메모 M01~M10 (Ch.06 §1)

| 메모 | 관찰된 문제 | 구현한 해결 방법 | 관련 파일 |

| M04 | 방 번호만으로는 수용 인원을 모름 | 카드마다 "4인실"을 크게 표시 | `app.js`, `style.css`, `data.js` |

| M09 | 인원수부터 고르고 남는 방만 보고 싶음 | 인원을 가장 먼저 선택, 빈 방만 표시 | `app.js` |
| M10 | 오터치 끝에 예약 포기 | 큰 버튼, 쉬운 되돌리기, 화면 전환 직후 연속 터치 무시 | `app.js`, `style.css` |

## 9. 검증 범위

PC의 Chrome을 휴대폰 화면(360px, 320px, 가로 640px)으로 설정하고 GitHub Pages와 같은 하위 경로에서 자동 점검했습니다. 예약 흐름, 인원 스테퍼, 뒤로가기와 조건 유지, 터치 영역과 간격, 가로 스크롤 없음, 화면에 표시된 글자의 실제 대비, 승인 실패와 재시도, QR 판독, 터치 스와이프로 다이얼 선택, 동작 줄이기 설정을 확인했습니다.

실제 스마트폰, 햇빛 아래 가독성, 실제 사용자의 완료 시간·오터치·복구 시간은 아직 측정하지 않았습니다. 사용자 테스트는 사이트의 테스트 모드로 진행할 수 있습니다.
