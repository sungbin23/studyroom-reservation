## 2. 5W1H 문제 정의
| 질문 | 작성란 |
|---|---|
| **Who**: 누구의 문제인가? | 조별 과제 모임 장소를 급하게 찾아 예약해야 하는 대학생 |
| **What**: 어떤 과업·문제인가? | 좁은 모바일 화면에서 복잡한 가로형 시간표(Time-grid)를 보고 빈 스터디룸을 찾아 예약하는 과업 |
| **When**: 언제 발생하는가? | 전공 수업이 끝난 직후 약 10분 남짓한 짧은 쉬는 시간 |
| **Where**: 어디서 발생하는가? | 학생들이 몰려나와 시끄럽고 복잡한 대학 건물 복도를 걸어가면서 |
| **Why**: 왜 중요한가? | 예약 실수나 지연으로 인해 조별 과제 일정이 꼬이거나, 학교 밖 비싼 유료 스터디 카페를 사비로 예약해야 하는 시간적·경제적 손실이 발생함 |
| **How**: 현재 어떻게 대처하는가? | 모바일 화면을 계속 확대/축소하거나 좌우로 스와이프하며 힘겹게 빈 시간을 확인하고, 오터치가 나면 처음부터 다시 시도함 |

### 문제 근거
| 근거 ID | 관찰·자료 내용 | 출처 | 신뢰도·한계 |
|---|---|---|---|
| **E01** | 스마트폰 화면에 꽉 찬 가로형 예약 시간표를 한눈에 보지 못해 좌우로 스와이프하다가 엉뚱한 시간대를 잘못 터치함 | 수업 직후 복도에서 모바일로 예약하는 학생 관찰 | 참여자 소수의 한 장면이며, 스마트폰 기종(화면 크기)에 따라 불편 정도가 다를 수 있음 |
| **E02** | "아, 도대체 지금 몇 시부터 몇 시가 비어있는 거야? 색깔 구분이 잘 안 가네." | 팀장이 단체 대화방에 남긴 불만 | 사용자의 일시적인 짜증 섞인 과장이 포함되었을 수 있음 |
| **E03** | 모바일 화면이 최적화되지 않고, PC 버전과 동일한 넓은 엑셀 표 형태의 UI가 그대로 축소되어 제공됨 | 도서관 모바일 웹사이트 예약 현황판 캡처 | 디자인 문제 외에도 서버 지연 등이 예약 실패에 영향을 줬을 수 있음 |

## 3. 프로젝트 목표
> `6주` 안에 `이동 중인 대학생`이 `스터디룸 모바일 예약 과업`을 수행할 때 `2분`인 `예약 완료 시간`을 `30초 이하`로 개선한다.

| SMART 기준 | 확인 내용 |
|---|---|
| **Specific** | 가로형 시간표를 '조건 입력 및 추천 리스트' 형태로 변경하여 예약 단계를 직관적으로 단순화함 |
| **Measurable** | 예약 완료 시간(초 단위) 및 뒤로가기/오터치 횟수를 명확히 측정함 |
| **Achievable** | 실제 시스템 개발이 아닌 Figma를 활용한 인터랙티브 프로토타입 제작 및 게릴라 사용성 테스트이므로 1인이 6주 내 충분히 달성 가능함 |
| **Relevant** | 모바일 환경에서의 예약 시간 단축은 이동 중 예약해야 하는 학생들의 가장 핵심적인 페인 포인트(Pain point)를 해결함 |
| **Time-bound** | 금주부터 시작하여 6주 이내에 평가까지 완료함 |

## 4. 범위와 산출물
| 포함 범위 | 제외 범위 | 제외 이유·후속 계획 |
|---|---|---|
| 조건(인원/시간) 입력 UI 화면 설계 | 내 예약 내역 관리 및 취소 기능 | 6주 안에 핵심 과업(빠른 탐색과 예약) 검증에만 리소스를 집중하기 위해 제외함 |
| 조건 기반 추천 리스트 UI 화면 설계 | 스터디룸 시설 안내 상세 페이지 | 정보 제공보다 인터랙션(예약 행동) 개선이 우선순위임 |
| 예약 완료(QR 출입증) 화면 설계 | 관리자용 스터디룸 승인/거절 페이지 | 학생 사용자 관점의 프론트엔드 UI에 국한하여 진행함 |

| 최종 산출물 | 형식·링크 | 완료 기준 |
|---|---|---|
| 연구 자료 | 사용자 관찰 기록 및 인터뷰 요약본 (PDF) | 대상자 3명 이상의 관찰/인터뷰 내용 포함 |
| 프로토타입 | Figma 인터랙티브 프로토타입 링크 | 조건 입력부터 예약 완료까지 끊김 없이 동작 |
| 평가 결과 | 사용성 테스트(UT) 결과 분석 리포트 (PDF) | 설정한 목표 지표(완료 시간, 오터치 횟수) 도달 여부 명시 |

## 5. 해결 가설과 성공 지표
| 해결 가설 | 지표 | 측정 방법 | 현재값 | 목표값 | 값의 성격 |
|---|---|---|---:|---:|---|
| 복잡한 시간표 대신 **'조건 입력 및 리스트 필터링' UI**를 제공하면, 사용자의 예약 과업 속도가 크게 향상될 것이다. | 예약 완료 시간 | 프로토타입 시작부터 완료 화면 도달까지 측정 | 2분 | 30초 이하 | 가상 |
| 시간대별 칸(Grid)을 터치하는 방식에서 **목록형 리스트 버튼**으로 변경하면, 조작 실수가 줄어들 것이다. | 오터치 및 취소 횟수 | 사용자가 의도와 다르게 화면을 터치하여 되돌아간 횟수 | 평균 3회 | 0회 | 가상 |

## 6. 6주 개인 수행 계획
| 주 | 핵심 활동 | 산출물 | 필요한 외부 협조 | 완료 기준 |
|---:|---|---|---|---|
| **1** | 문제 정의 및 제안서 작성 | 프로젝트 제안서 (5W1H, SMART) | 없음 | 제안서 작성 완료 및 목표 확정 |
| **2** | 기존 시스템 사용성 리서치 | 관찰 및 간단한 인터뷰 기록 | 도서관 이용 학생 3명의 인터뷰 협조 | 페인 포인트 3가지 이상 도출 |
| **3** | 정보 구조 재설계 및 3프레임 기획 | 종이 프로토타입 (Paper 스케치) | 없음 | 핵심 화면 3개 스케치 완료 |
| **4** | 디지털 프로토타입 제작 | Figma 인터랙티브 프로토타입 | 없음 | 화면 간 전환 액션 구현 완료 |
| **5** | 사용자 테스트(UT) 진행 | UT 진행 기록 및 피드백 시트 | 학생 3명의 테스트 협조 | 테스트 3건 완료 및 정량 데이터 수집 |
| **6** | 평가 분석 및 최종 결과 보고 | 최종 결과 보고서 (PDF) | 없음 | 성공 지표 달성 여부 분석 완료 |

## 7. 개인 작업 관리
| 업무 영역 | 내가 수행할 일 | 도움받을 수 있는 사람·자료 | 의사결정 기준 |
|---|---|---|---|
| **사용자 연구** | 이동 중인 학생 대상 게릴라 관찰 및 인터뷰 진행 | 동기 및 후배 학생들 | 실제 이동 맥락(Context)을 반영할 수 있는가? |
| **디자인/기술** | 조건 필터링 기반 UI 디자인, 도서관 서버의 데이터 처리 타당성 검토 | 기존 학내 도서관 API 구조 참고 자료 | 벡엔드에서 실시간 필터링 처리가 가능한 구조인가? |
| **프로토타입** | Figma를 활용한 모바일 화면 설계 및 인터랙션 구현 | Figma 커뮤니티 UI 키트 | 핵심 과업(예약) 흐름이 단절 없이 이어지는가? |
| **평가·분석** | UT 결과 데이터를 바탕으로 목표 시간(30초) 달성 여부 검증 | 사용성 평가 리포트 템플릿 | 수집된 데이터가 가설을 명확히 증명 또는 반증하는가? |

> **과업이 지연될 때 축소할 최소 범위:**
> 프로토타입의 시각적 디자인 고도화 작업을 최소화하고, 와이어프레임 수준의 흑백 프로토타입으로 즉시 사용성 테스트(UT) 단계로 넘어가 기능 작동 여부만 우선 검증한다.

## 8. 위험과 대응
| 위험 | 가능성 | 영향 | 예방·대응 | 확인 시점 |
|---|---:|---:|---|---|
| **참여자 모집 실패** | 2 | 3 | 복잡한 실험실 세팅 대신, 복도에서 3분 이내로 참여 가능한 '게릴라 테스트'로 접근하여 참여 허들을 낮춤. 기프티콘 준비. | 2주차, 5주차 |
| **범위 확대 (Scope Creep)** | 3 | 2 | 다른 아이디어가 떠오르더라도 철저히 '조건 필터링 예약' 단일 과업에만 집중하도록 일정표 매일 확인. | 3주차 (기획 단계) |
| **기술 구현 불가** | 1 | 3 | 기존 시스템이 필터링 데이터를 반환할 수 없을 경우를 대비해, 기존 표(Time-grid)를 모바일에 맞게 '세로형'으로 전환하는 차선책 UI를 1안으로 백업. | 3주차 |

## 9. 3분 자기 제안 검토
| 점검 | 결과·수정 내용 |
|---|---|
| **문제와 근거를 30초 안에 설명했는가?** | "학생들이 짧은 공강 시간에 복잡한 가로형 표를 조작하다 예약을 실패하는 현상을 관찰했습니다."로 명확히 설명 가능함. |
| **사용자 가치와 성공 지표가 연결되는가?** | 빠른 예약이라는 가치가 '30초 이내 완료'라는 효율성 지표와 직결됨. |
| **1인이 6주 안에 수행 가능한 범위인가?** | 실제 코드 구현을 배제하고 단일 과업 프로토타이핑에 집중하여 가능함. |
| **가장 위험한 가정을 먼저 시험하는가?** | 사용자가 전체 현황표를 포기하고 추천 리스트 방식을 신뢰할 것인가를 최우선으로 검증함. |
